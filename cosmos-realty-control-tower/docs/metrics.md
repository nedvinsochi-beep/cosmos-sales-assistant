# Метрики MVP

## Движок правил контроля

- `MISSED_LEAD_ACCEPTANCE`: назначенный брокеру лид остался в `NEW` к 23:50;
  без надёжного `assigned_at` результат `BLOCKED_BY_DATA`.
- `NO_NEXT_STEP`: карточка оперативного периметра не имеет будущей
  CRM-активности и связанной будущей задачи; без полного покрытия задач результат
  `BLOCKED_BY_DATA`.
- доля без следующего шага: подтверждённые карточки без шага / активные карточки
  брокера; заблокированные данные не включаются в числитель.
- время устранения, повторы и динамика рассчитываются только по накопленному
  журналу нескольких запусков.

## CRM-дисциплина

- `NO_NEXT_TASK`: подтверждённое отсутствие открытой следующей активности.
- `OVERDUE_TASK`: дата следующей активности раньше текущего времени UTC.
- `NO_FIRST_CALL`: отсутствие первого звонка по подтверждённым данным активности.
- `INACTIVE_ENTITY`: время с последней CRM-активности превышает 24/48/72 часа;
  для старых снимков без активности допускается явно отмеченный fallback.
- `UNACCEPTED_LEAD`: новый лид не принят за настроенный норматив и не имеет
  активности.
- `STAGE_AGE`: время на стадии превышает норматив конкретной стадии.
- `REQUIRED_FIELD`: отсутствует поле, явно назначенное обязательным для стадии.

Если источник, тип активности, поле или норматив не подтверждён, результат
правила — `BLOCKED_BY_DATA`, а не нарушение.

## Базовые агрегаты

- Число сущностей брокера: количество записей с одним `assigned_to_id`.
- Число сущностей отдела: количество записей с одним `department_id`.
- Число нарушений: количество результатов со статусом `VIOLATION`.
- CRM-дисциплина брокера: доля его активных карточек, по которым не найдено ни
  одного подтверждённого нарушения. `BLOCKED_BY_DATA` нарушением не считается.

Все периоды считаются в UTC; исходная временная зона должна быть записана после
её обнаружения в Bitrix24.

`DATE_MODIFY` live-карточки не считается доказательством контакта с клиентом.
Конверсии между стадиями не рассчитываются до появления истории переходов.
