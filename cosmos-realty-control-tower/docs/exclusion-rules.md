# Правила исключений

## Можно применять безопасно после подтверждения владельца

| Исключение | Почему | Текущий результат |
| --- | --- | --- |
| Закрытая карточка | Не требует текущего следующего шага | 6 416 |
| Успешно завершённая сделка | Работа завершена | Входит в закрытые |
| Неактивный сотрудник | Нельзя оценивать как текущую дисциплину сотрудника | 309 карточек, 15 открытых |
| Учебная/техническая воронка | Не является продажной работой | Категории 10 и 12; карточек в снимке нет |
| Риелторское сотрудничество `UC_OWVT1B` | Не является клиентом-покупателем | Сейчас кандидат на исключение |

## Требуют отдельного решения

| Категория | Почему нельзя решить автоматически |
| --- | --- |
| Историческая карточка без активности | Она может быть забытым клиентом либо старой базой для повторной обработки |
| Статус `NEW` старше периода | В базе 14 112 таких статусов; нет подтверждённой даты принятия |
| `НЕДОЗВОН` | Может требовать нормативного числа новых попыток, а не исключения |
| Прогрев | Нужны дата следующего касания и регламент по сегменту |
| Допустимое ожидание | Нужен список стадий и максимальные сроки |
| Нет следующей задачи | Не по каждой стадии задача обязательно нужна |
| Нецелевой лид | Нужна заполненная и утверждённая причина закрытия |

## Пока невозможно определить надёжно

- дубли: для безопасного аудита не читались телефоны, email и идентификаторы
  объединения дублей;
- тестовые и системные записи: не найден утверждённый флаг;
- причина закрытия: единое обязательное поле не подтверждено;
- старая база, выданная брокеру повторно: нет отдельной даты повторной выдачи;
- обязательство иметь следующую задачу: нет матрицы по стадии;
- время на стадии: `crm.stagehistory.list` недоступен текущему webhook;
- факт звонка: provider ID звонка ещё не утверждён;
- встреча состоялась: `COMPLETED` не доказывает участие клиента.

## Плохое заполнение данных

- у 10 849 карточек нет найденной последней CRM-активности;
- у 20 774 нет открытой следующей активности;
- 14 112 лидов остаются в `NEW`, включая исторические;
- 309 карточек закреплены за неактивными сотрудниками;
- 53 карточки не имеют источника;
- сумма комиссии и дата поступления не подтверждены;
- история стадий отсутствует в доступном REST-контуре.

## Что изменить в регламенте

1. Зафиксировать событие «лид принят» и его срок.
2. Утвердить матрицу «стадия → обязательная следующая задача → норматив».
3. Разделить прогрев, недозвон, ожидание и архив.
4. Ввести дату повторной выдачи старой базы брокеру.
5. Обязать выбирать причину потери из справочника.
6. Переназначить или архивировать открытые карточки неактивных сотрудников.
7. Утвердить типы звонков, встреч и показов.

## Когда безопасно включать роботов

Только после письменного утверждения пунктов 1–7, недельного наблюдения за
dry-run без массовых ложных тревог и ручной проверки выборки минимум по 20
карточек каждого правила. До этого реальные уведомления и изменения CRM должны
оставаться выключенными.
