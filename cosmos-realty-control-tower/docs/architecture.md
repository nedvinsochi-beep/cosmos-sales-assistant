# Архитектура

## Границы MVP

Система только читает данные Bitrix24. `BitrixClient` пропускает исключительно
методы из явного списка `READ_ONLY_METHODS`; любой другой метод блокируется до
сетевого обращения.

Поток данных:

1. CLI загружает локальную конфигурацию.
2. Клиент проверяет подключение, методы и метаданные.
3. Персональные поля маскируются.
4. Нормализованные записи проверяются правилами.
5. Результаты сохраняются локально в `output/`.

## Почему без pandas/polars и pyarrow

CR-BI-001–005 не требуют обработки больших таблиц до получения реальной
инвентаризации. Стандартные структуры Python уменьшают зависимости MVP.
Табличный движок и Parquet будут выбраны после измерения объёма и доступных
методов Bitrix24, а не заранее.

## Трассировка

Каждое нарушение содержит `entity_type`, `source_id`, `rule_id`, статус и
минимальный набор доказательств без клиентских персональных данных.
