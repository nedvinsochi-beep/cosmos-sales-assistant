# Правила автоматического контроля РОПа

## Что работает сейчас

Команда `cosmos-control report` читает только структурные поля Bitrix24, считает
нарушения и формирует экран и отчёты. Клиентские ФИО, телефоны, email, тексты и
документы не запрашиваются.

| Правило | Что проверяется | Кому адресуется dry-run | Ограничение |
| --- | --- | --- | --- |
| `UNACCEPTED_LEAD` | Новый лид без активности дольше норматива | Брокер | Норматив по умолчанию 15 минут, требует утверждения |
| `NO_FIRST_CALL` | Нет подтверждённого звонка | Брокер | До утверждения provider ID результат `BLOCKED_BY_DATA` |
| `NO_NEXT_TASK` | Нет открытой следующей активности | Брокер | Используются CRM-активности |
| `OVERDUE_TASK` | Deadline открытой активности прошёл | Брокер | Перенос и закрытие не выполняются |
| `INACTIVE_ENTITY` | Нет активности 24/48/72 часа | Брокер → РОП → собственник | 48/72 часа меняют адресата preview |
| `STAGE_AGE` | Сделка находится на стадии сверх норматива | РОП | До утверждения нормативов `BLOCKED_BY_DATA` |
| `REQUIRED_FIELD` | На стадии отсутствует обязательное поле | Брокер | До утверждения полей `BLOCKED_BY_DATA` |

## Гарантии dry-run

- в `BitrixClient` разрешены только методы из read-only allowlist;
- неизвестный или write-метод блокируется до сетевого запроса;
- `preview_actions` создаёт только локальные объекты с `dry_run=true`;
- в CSV и HTML явно указано «НЕ ВЫПОЛНЕНО»;
- в коде роботов нет вызовов Bitrix24;
- включение реальных действий требует отдельной задачи, отдельного allowlist и
  отдельной проверки безопасности.

## Что увидит РОП

1. «Сегодня» — непринятые лиды, отсутствие следующего шага, просрочки и
   неактивность.
2. «Брокеры» — нагрузка, нарушения, показы, брони, сделки и уровень риска.
3. «Воронка» — честный текущий срез по стадиям. Конверсия скрыта, если истории
   нет.
4. «Контроль» — причина, ID и ссылка на карточку, рекомендуемое действие и срок.
5. «Dry-run роботов» — кому и что система предложила бы отправить или сделать.

## Что нужно утвердить перед включением автоматизации

- норматив принятия нового лида;
- точные provider ID телефонных звонков;
- норматив времени для каждой стадии;
- обязательные поля каждой стадии;
- причины потери;
- порядок эскалации брокер → РОП → собственник;
- текст и канал каждого уведомления.
