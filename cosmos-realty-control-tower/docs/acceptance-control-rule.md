# Робот «Потеряшка»: утверждённое правило принятия лида

## Бизнес-смысл

`Новый лид — раздача` (`NEW`) — временная техническая стадия. Брокер подтверждает
принятие только переходом в `Взял / касание` (`IN_PROCESS`) или следующую рабочую
стадию. Звонок, комментарий и иная активность не заменяют смену стадии.

Проверка выполняется ежедневно в 23:50 `Europe/Moscow`. Время выдачи лида не даёт
отсрочки: если назначенный конкретному брокеру лид остался в `NEW`, SLA нарушен.

## Отбор и исключения

Кандидат должен быть открытым лидом основной рабочей воронки, иметь конкретного
действующего брокера и подтверждённую дату назначения в проверяемый день. Из
контроля исключаются общий пул, РОПы, собственник, служебные, технические,
тестовые и неактивные пользователи. Идентификаторы исключений задаются только в
локальной копии `config/organization-map.example.json`.

## Preview будущего действия

Dry-run показывает переназначение на РОПа, добавление прежнего брокера и
пользователя «Потеряшка» наблюдателями, служебный комментарий, признаки
`MISSED_ACCEPTANCE_SLA` и `AUTO_RETURNED_TO_ROP`, а также ключ идемпотентности.
Один и тот же случай не должен обрабатываться повторно.

```bash
uv run cosmos-control acceptance-control --dry-run --as-of "23:50"
```

Команда применения подготовлена как интерфейс, но намеренно закрыта safety-gate:

```bash
uv run cosmos-control acceptance-control --apply
```

Она завершается до подключения к Bitrix24 и выполняет ноль записей.

## Подтверждённый блокер данных

Доступная схема Bitrix24 содержит текущий `ASSIGNED_BY_ID`, но не время, когда
этот ответственный был назначен. `DATE_CREATE`, `DATE_MODIFY` и `MOVED_TIME`
имеют другой смысл и не подменяются датой назначения. Поэтому точные показатели
«назначено сегодня», «принято до 23:50» и список к реальному возврату сейчас
имеют статус `BLOCKED_BY_DATA`.

Для включения робота нужен надёжный `assigned_at`: например, локальный журнал
событий назначения с момента запуска или отдельно утверждённое поле/событие в
CRM. Также собственник должен подтвердить полную organization-map и ID
«Потеряшки». До этого отчёт показывает только честные прокси и заблокированных
кандидатов, не изменяя CRM.

## Расписание

`deploy/com.cosmos.acceptance-control.plist.example` — шаблон локального запуска
dry-run в 23:50. Он не установлен и не активирован. В нём нет `--apply`.
