# COSMOS REALTY CONTROL TOWER
## Техническое задание на BI- и AI-систему управления продажами

**Версия:** 0.1 — архитектура и MVP  
**Назначение:** постановка задач Codex / Bitrix24-разработчику / вайб-кодеру / BI-аналитику  
**Система-источник:** Bitrix24  
**Компания:** Cosmos Realty  
**Предмет:** курортная и инвестиционная недвижимость

---

# 1. Цель проекта

Создать единую цифровую систему управления Cosmos Realty, которая:

1. автоматически собирает фактические данные из Bitrix24;
2. разделяет показатели по управленческим ролям;
3. показывает брокеру только его рабочую зону;
4. показывает РОПу состояние отдела и конкретные отклонения;
5. показывает собственнику не деятельность брокеров, а качество управления РОПов;
6. выявляет искажения CRM-дисциплины;
7. прогнозирует выполнение плана;
8. формирует ежедневные AI-сводки и рекомендации;
9. не требует ручной подготовки отчетов;
10. постепенно превращает Bitrix24 из хранилища карточек в операционную систему продаж.

Главный принцип:

> Собственник не управляет брокерами. Собственник управляет руководителями, системой и экономикой. РОП управляет брокерами. AI контролирует достоверность данных и качество управленческой работы.

---

# 2. Проблема, которую решает система

- РОПы не живут в CRM;
- брокеры заполняют карточки задним числом;
- активность может имитироваться;
- этапы сделок не соответствуют фактическому состоянию клиента;
- задачи не ставятся или закрываются формально;
- собственник вынужден лично проваливаться до уровня отдельных лидов;
- отчеты строятся вручную и запаздывают;
- планерки строятся на мнениях, а не на доказуемых данных;
- нельзя точно определить, где причина просадки: лиды, брокеры, РОП, маркетинг или процесс;
- выполнение плана оценивается слишком поздно;
- нет объективной оценки управленческой активности РОПа;
- финансовые и операционные показатели не связаны.

# 3. Архитектура ролей

## 3.1. Брокер

Отвечает за принятие лида, первый контакт, касания, квалификацию, обязательные поля, следующий шаг, видеовстречу, показ, бронь, сопровождение и фиксацию результата в CRM.

## 3.2. РОП

Отвечает за результат отдела, план, CRM-дисциплину, скорость обработки, распределение нагрузки, прослушивание звонков, разборы, обучение, прогноз, вмешательство в проблемные сделки и недопущение «кладбища лидов».

РОП не должен вручную собирать отчеты. Его задача — принимать решения по уже подготовленным данным.

## 3.3. Собственник / директор по развитию

Отвечает за результат компании, качество управления РОПов, финансовую устойчивость, организационную архитектуру, нормативы, ресурсы, масштабирование, маркетинговую эффективность, кадровые решения и стратегию.

## 3.4. AI-аудитор

Ищет незаполненные поля, сделки без задач, зависшие лиды, нарушения SLA, аномальную активность, несоответствие звонков и стадий, вероятное «рисование CRM» и формирует доказательную базу.

## 3.5. AI-аналитик собственника

Агрегирует показатели отделов, рассчитывает индекс эффективности РОПов, прогнозирует выполнение плана, объясняет отклонения и предлагает решения.

5. Квалификация.
6. Прогрев / подбор.

8. Видеовстреча состоялась.
9. Показ / КЭВ назначен.

11. Бронь.
12. Сделка.
13. Ожидание комиссии.
14. Комиссия получена.

# 9. Индекс эффективности РОПа

Предварительные веса:

- 30% — выполнение плана;
- 15% — прогнозируемое выполнение;
- 15% — CRM-дисциплина отдела;
- 10% — конверсия отдела;
- 10% — скорость обработки;
- 10% — управленческая активность;
- 5% — качество прогноза;
- 5% — удержание и развитие команды.

Ограничители: нельзя получить высокий балл при критической CRM-недисциплине, массовом отсутствии задач, недостоверных прогнозах и бездействии РОПа.

# 10. AI-аудит CRM

Проверки MVP:

1. Новый лид не принят вовремя.
2. Нет первого звонка.
3. Нет обязательного числа попыток.
4. Нет следующей задачи.
5. Задача закрыта без результата.
6. Сделка переведена без обязательных полей.
7. Комментарий не подтверждает стадию.
8. Звонок не соответствует указанному результату.
9. Массовое закрытие задач.
10. Массовое заполнение карточек задним числом.
11. Сделка стоит без движения.
12. РОП не отреагировал на нарушение.

# 11. MVP

## Этап 0. Аудит

Определить тип Bitrix24, тариф, воронки, стадии, поля, структуру, пользователей, BI-датасеты, телефонию, записи звонков, UTM и качество данных.

## Этап 1. BI

Создать:

1. оперативный дашборд РОПа;
2. CRM-дисциплину;
3. просроченные и зависшие лиды;
4. воронку по отделам;
5. конверсии по брокерам;
6. план-факт;
7. контроль РОПов для собственника.

## Этап 2. Уведомления

Автоматические сигналы о лидах без первого звонка, карточках без задач, просрочках, превышении времени стадии, падении конверсии и риске невыполнения.

## Этап 3. AI-сводки

Ежедневная сводка РОПу, собственнику и недельный управленческий отчет.

## Этап 4. Анализ звонков

Транскрибация, оценка скрипта, выявление потребности, возражений, следующего шага, вероятности сделки и рекомендаций.

# 13. Критерии готовности MVP

1. Данные автоматически читаются из Bitrix24.
2. Ручная подготовка таблиц не требуется.
3. Каждый сотрудник привязан к отделу и РОПу.
4. Видны лиды без задач и просрочки.
5. Видна скорость реакции.
6. Видна воронка по брокерам и отделам.
7. Есть план-факт.
8. Есть прогноз.
9. Есть рейтинг РОПов.
10. Есть ежедневный отчет с объяснениями.
11. Показатели трассируются до карточки CRM.
12. Система не изменяет данные без отдельного разрешения.
