# Команда запуска для Codex

Скопируй весь блок ниже и передай Codex.

```text
Работай с GitHub-репозиторием:
https://github.com/nedvinsochi-beep/cosmos-sales-assistant

Твоя задача — начать разработку проекта Cosmos Realty Control Tower.

Обязательный порядок:

1. Клонируй репозиторий.
2. Прочитай полностью:
   - README.md
   - AGENTS.md
   - docs/Cosmos_Realty_Control_Tower_TZ_v0.1.md
3. Создай отдельную ветку:
   feat/bitrix-audit-mvp
4. До отдельного разрешения работай с Bitrix24 только в READ-ONLY режиме.
5. Не выдумывай названия полей, стадии, ID, вебхуки, токены, тариф и доступные методы.
6. Если подключение Bitrix24 еще не настроено, сначала подготовь безопасный проект, конфигурацию и точную инструкцию, какие секреты и доступы нужно добавить локально. Секреты в GitHub не коммить.
7. Выполни задачи CR-BI-001 — CR-BI-005 из ТЗ.

Создай структуру:

cosmos-realty-control-tower/
  pyproject.toml
  .env.example
  .gitignore
  README.md
  docs/
    architecture.md
    data-audit.md
    data-dictionary.md
    metrics.md
    open-questions.md
    security.md
  schemas/
  sql/
  src/cosmos_control_tower/
    bitrix/
    models/
    metrics/
    audit/
    reports/
    cli/
  tests/
  output/.gitkeep

Предпочтительный стек при отсутствии существующего кода:

- Python 3.12
- uv
- httpx
- pydantic-settings
- tenacity
- pandas или polars — выбери обоснованно
- pyarrow
- jinja2
- typer
- pytest
- pytest-asyncio
- ruff
- mypy

Реализуй:

A. Конфигурацию
- BITRIX_WEBHOOK_URL только через .env;
- таймауты;
- лимиты;
- логирование;
- режим маскирования персональных данных.

B. Read-only Bitrix24 client
- универсальный вызов REST;
- batch при уместности;
- пагинацию;
- retry/backoff;
- rate limiting;
- обработку ошибок;
- структурированные логи;
- методы чтения пользователей, подразделений, лидов, сделок, дел, задач, звонков, стадий и пользовательских полей — только если методы доступны.

C. Команду аудита
Пример:
uv run cosmos-control audit-bitrix

Она должна:
- проверить подключение;
- определить доступные методы и scopes настолько, насколько это возможно;
- выгрузить метаданные без клиентских персональных данных;
- сформировать docs/data-audit.md;
- сформировать docs/data-dictionary.md;
- сформировать docs/open-questions.md;
- сохранить обезличенные технические результаты в output/.

D. CRM audit MVP
Подготовь архитектуру и код правил:
- лид без следующей задачи;
- просроченная задача;
- отсутствует первый звонок;
- отсутствует активность заданное время;
- превышен норматив нахождения на стадии;
- обязательное поле не заполнено.

Поскольку реальные поля и нормативы могут быть неизвестны:
- вынеси правила в конфигурацию;
- не придумывай ID;
- добавь пример конфигурации;
- отмечай непроверяемые правила как BLOCKED_BY_DATA.

E. Отчеты
Сформируй шаблоны:
- output/violations.csv;
- output/broker_metrics.csv;
- output/department_metrics.csv;
- output/daily_report.html;
- output/daily_report.md;
- output/daily_report.json.

F. Тесты
Добавь тесты:
- пагинации;
- retry;
- маскирования персональных данных;
- правил нарушений;
- расчетов базовых метрик;
- генерации отчетов.

G. Документация
Зафиксируй:
- что реально обнаружено;
- что пока является гипотезой;
- какие данные отсутствуют;
- какие доступы нужно предоставить;
- что будет следующим этапом.

Безопасность:
- никаких write-запросов в Bitrix24;
- никаких секретов в git;
- никаких ФИО, телефонов, email и текстов разговоров в fixtures/output;
- не использовать production-данные в тестах;
- любое потенциально опасное действие остановить и описать.

По завершении:
1. запусти тесты, ruff и mypy;
2. обнови документацию;
3. сделай коммиты;
4. push ветку;
5. открой DRAFT pull request в main;
6. в PR укажи:
   - что сделано;
   - результаты аудита;
   - ограничения;
   - открытые вопросы;
   - точную инструкцию следующего запуска.

Не останавливайся на плане. Реализуй всё, что возможно без отсутствующих секретов. Если Bitrix24 недоступен, полностью подготовь код, mock/fixtures, тесты, CLI и документацию, чтобы после добавления .env аудит запускался одной командой.
```
